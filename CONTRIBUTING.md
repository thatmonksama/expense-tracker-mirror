# Contributing

Thank you for contributing to Expense Tracker.

## Reporting Issues

Before creating an issue, check whether a similar issue already exists.

When reporting a problem, include:

- A clear description of the problem
- The expected behavior
- The observed behavior
- Relevant steps to reproduce the problem

Do not include passwords, account credentials, personal financial information, or other sensitive data in issues.

## Documentation Changes

Documentation improvements are welcome.

Keep documentation concise and ensure that examples remain consistent with the repository's current structure.

## Data Changes

Sample expense data should remain synthetic.

Do not add real financial records, personal information, account numbers, payment details, or other sensitive information.

## Commit Messages

Use short and descriptive commit messages.

Examples:

- `docs: improve installation instructions`
- `data: add sample expense records`
- `docs: update usage examples`

## Pull Requests

Pull requests should describe:

1. What was changed
2. Why the change was made
3. Any relevant issues

Reviewers should verify that documentation, sample data, and configuration examples remain consistent.
